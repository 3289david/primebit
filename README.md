# 코인 환전소 (디스코드 봇) — 예시 브랜드: PrimeBIT

원화 충전 → 입금 자동인식 → 포인트 지급 → 코인 구매 시 내 지갑에서 유저 지갑으로 자동 송금 → 블록 확정 후 DM.

> 이 저장소는 템플릿입니다. "PrimeBIT"는 예시 브랜드명일 뿐이며, 샵 이름/색상/도메인/채널 등은
> 전부 `.env` 설정으로 바꿀 수 있습니다 — 자세한 내용은 [커스터마이징](#커스터마이징-다른-브랜드로-운영하기) 참고.

```
유저 ─(충전 신청: 입금자명+금액)─▶ 봇이 입금계좌 안내
유저 ─(관리자 계좌로 송금)─▶ 은행 문자/푸시 ─▶ [안드로이드 앱] ─(HMAC 서명)─▶ POST /api/deposit
                                                       이름+금액 일치 ▶ 포인트 100% 지급 + DM
유저 ─(코인 구매: 코인·주소·포인트)─▶ 수수료 3% 공제 → 나머지 97%치 코인 ─▶ 핫월렛이 유저 주소로 송금
                                      └▶ 전송됨(DM) → 블록 확정 감시(15초 주기) → 확정 시 DM + 탐색기 링크
```

## 기능
- **유저(디스코드)**: 본인인증(휴대폰+KYC) / 충전 / 코인 구매 / 매입 신청 / 내 정보 / 내역 / 계산기 / 문의 티켓 · 지난번 주소 자동 입력 · 견적 60초 확정 단계
- **본인인증 / KYC**: 충전·구매 전 **휴대폰 본인인증 + KYC 승인**을 반드시 통과해야 함 (자세한 내용은 [아래 섹션](#본인인증--kyc) 참고)
- **자동 DM**: 충전 완료·만료 / 코인 전송 시작 / 블록 확정(탐색기 링크) / 주문 문제 발생 / 환불 / 포인트 조정 / 매입 처리 / 이용 제한·해제 / KYC 승인·반려
- **현황**: 임베드(30초 갱신) + 음성채널 시세판(환율·김프·주요 재고, 6분 갱신) + 재고 부족/재입고/수수료(가스) 부족 알림(충전 주소 포함) + 공개 거래 로그(이름 마스킹)
- **관리자 패널** `{PUBLIC_URL}/admin` (디스코드 OAuth 로그인)
  - 대시보드: 총 재고 가치, 오늘/누적 수수료 수익, 7일 그래프, 점검 모드, 디스코드 공지, CSV 내보내기
  - **재고/지갑**: 체인별 **재고 충전 주소(복사)**, 코인별 재고·시세·가치·상태, **보충 권장 수량**, 가스 잔액 경고, 코인별 판매 중지/재개
  - 충전·입금(미매칭 수동 매칭)·주문(탐색기 링크, 재전송/환불)·매입·**본인인증/KYC(증빙 확인 후 승인/반려)**·유저(포인트 조정/차단)·포인트 로그·**감사 로그**·설정
- **긴급 관리**: 디스코드 `/관리자 점검모드`, `/관리자 공지` 명령으로 웹 패널 없이도 즉시 점검모드 전환/공지 방송 가능
- **보안 알림**: 관리자 패널 로그인 성공/거부 시도가 관리자 로그 채널로 실시간 통보
- **안전장치**: 본인인증/KYC 승인 완료 유저만 충전·구매 가능, 1인 1일 구매 한도, 점검 모드, 송금 체인별 직렬 처리, 실패 시 자동 재전송/환불 없이 `error` 보관(이중 송금 방지)

## 본인인증 / KYC

충전·코인 구매는 **휴대폰 본인인증**과 **KYC 승인**을 모두 마친 유저만 가능합니다 (`src/services/points.js`의
`assertVerified` — 충전/구매 서비스 함수 내부에서 강제되므로 디스코드 어느 경로로도 우회할 수 없습니다).

1. **휴대폰 본인인증** — 메인 패널 "🛡️ 본인인증" 버튼 → 휴대폰 번호 입력 → 6자리 코드 발급
   - [Octomo](https://octomo.octoverse.kr) 의 **"번호 소유 확인"** API를 사용합니다. 유저가 안내된 대표번호(`1666-3538`)로
     발급된 코드를 **직접 문자로 전송**하면, 서버가 Octomo API(`POST /octomo/v1/public/message/exists`)로 수신 여부를 조회합니다.
   - ⚠️ 이것은 **주민등록번호 대조·실명 확인이 아닌 "그 번호를 실제로 쓰고 있는지"만 확인**하는 전화번호 소유 검증입니다.
     한국의 법정 본인인증(PASS/NICE/KCB 등 CI·DI 기반)이 필요하다면 별도 제휴사 연동이 필요합니다.
   - "문자 보내기" 버튼(모바일에서 문자 앱이 코드 채워진 채 열림) 또는 QR 코드(PC로 보고 있을 때 폰 카메라로 스캔)로 전송 → "인증 확인" 클릭
   - `.env` 의 `OCTOMO_API_KEY` 필요 (Octomo 가입 후 마이페이지에서 발급)
2. **KYC (신원 증빙, 관리자 수동 승인)** — 휴대폰 인증 후 같은 버튼으로 실명/생년월일 입력 →
   전용 비공개 채널(`kyc-유저명`, `TICKET_CATEGORY_ID` 카테고리 아래 생성)이 만들어지고, 유저가 그 채널에
   신분증 사진을 첨부합니다.
   - 관리자가 그 채널의 **승인/반려 버튼**을 누르거나, 관리자 패널의 **"본인인증/KYC" 탭**에서 동일하게 처리할 수 있습니다.
   - 반려 시 사유를 입력하면 유저에게 DM으로 전달되고, 다시 제출할 수 있습니다.
   - 승인/반려 모두 관리자 로그 채널에 기록됩니다.
   - 자동화된 서류 진위 확인(OCR/안면인식 등)은 **포함되어 있지 않습니다** — 관리자가 직접 사진을 눈으로 확인하고 승인하는 구조입니다.
     더 엄격한 KYC가 필요하면 별도 KYC 벤더(예: 나이스, Sumsub 등) 연동이 필요합니다.

## 설치
1. 디스코드 개발자 포털
   - **Bot**: 토큰 발급 → 서버에 초대 (권한: 채널 관리, 역할 관리, 메시지 전송, 임베드)
   - **OAuth2**: Client ID/Secret 확인, Redirects 에 `{PUBLIC_URL}/admin/callback` 추가 (예: `https://exchange.example.com/admin/callback`)
2. [Octomo](https://octomo.octoverse.kr) 가입 → API Key 발급 (휴대폰 본인인증용)
3. `.env.example` → `.env` 복사 후 값 채우기
   - `ADMIN_DISCORD_IDS` 에 본인 디스코드 ID
   - `SHOP_NAME`, `BRAND_COLOR` 로 브랜드 지정 ([커스터마이징](#커스터마이징-다른-브랜드로-운영하기) 참고)
   - `OCTOMO_API_KEY` 에 발급받은 키
4. 도메인/HTTPS: 사용할 도메인의 DNS A 레코드를 서버 IP로, [deploy/Caddyfile](deploy/Caddyfile) 의 도메인을 실제 도메인으로 바꾼 뒤 Caddy 실행 (인증서 자동).
   `.env` 의 `PUBLIC_URL` 과 반드시 동일해야 합니다.
5. 실행
   ```bash
   npm install
   npm run check:chains -- --probe   # RPC/토큰 컨트랙트 점검 (읽기 전용)
   npm start
   ```
6. 디스코드에서 관리자 계정으로: `/setup panel`, `/setup status`, `/setup voice`
   (또는 `.env` 에 `PANEL_CHANNEL_ID`/`STATUS_CHANNEL_ID` 를 지정해두면 봇이 처음 켜질 때 그 채널에 자동 설치)
7. 관리자 패널 접속 → **설정 탭에서 입금 계좌 입력** → **재고/지갑 탭의 주소로 코인 입금**(가스용 네이티브 코인 포함)

### 관리자 로그인
비밀번호 로그인은 없습니다. 디스코드 OAuth 로 로그인하며, `ADMIN_DISCORD_IDS` 에 있거나 서버에서 `ADMIN_ROLE_ID` 역할을 가진 계정만 통과합니다. 모든 변경 작업은 감사 로그에 기록됩니다.

## 안드로이드 입금감지 앱
`android/` 를 Android Studio 로 열어 빌드 → 입금 문자를 받는 폰에 설치.
1. 서버 주소 (`.env` 의 `PUBLIC_URL`, 예: `https://exchange.example.com`) 와 `DEVICE_SECRET` 입력 → 저장
2. 알림 접근 권한 · 문자 수신 권한 · 배터리 최적화 제외
3. "서버 연결 테스트"
- 서버는 **입금자명 + 금액이 모두 일치**하는 대기 중 충전만 자동 지급. 불일치는 패널 > 입금내역에서 수동 매칭
- 전송 실패 시 폰에 큐로 보관 후 재시도, 서버는 해시로 중복 제거

## 운영 전 꼭 확인
- **개인키는 `.env` 에 평문 저장됩니다.** 소액만 두고, 서버 접근을 통제하세요. 처음에는 **소액으로 체인별 1건씩 실전송 테스트**를 권장합니다.
- 체인별 수수료용 네이티브 코인(TRX/ETH/BNB/POL/AVAX/SOL/XRP)과 BTC 확정 UTXO가 있어야 송금됩니다.
- 공용 RPC는 제한/불안정할 수 있어 운영에서는 전용 RPC(`RPC_*`)를 권장합니다.
- Solana/XRP는 전송 후 일정 시간 원장에 안 보이면 `error`(드롭 추정)로 표시합니다. 탐색기에서 미전송을 확인한 뒤 재전송하세요.
- 법률: 원화↔가상자산 교환 영업은 **가상자산사업자(VASP) 신고·AML(특금법)** 대상일 수 있습니다.
- [본인인증/KYC](#본인인증--kyc) 섹션 참고: 휴대폰 인증은 "번호 소유 확인"일 뿐 법정 실명 확인이 아니며, KYC는 관리자 수동 승인입니다.
  더 높은 수준의 인증이 법적으로 필요한 경우 별도 검토·연동이 필요합니다.

## 커스터마이징 (다른 브랜드로 운영하기)

이 코드를 그대로 가져다 **다른 이름/도메인/서버로 운영**하려면 아래만 바꾸면 됩니다 — 코드 수정은 필요 없습니다.

| 바꾸고 싶은 것 | 설정 위치 |
|---|---|
| 샵/봇 이름 (임베드, 음성채널, 관리자 패널 제목 전체) | `.env` 의 `SHOP_NAME` |
| 브랜드 색상 (임베드 테두리색) | `.env` 의 `BRAND_COLOR` (hex, `#` 없이) |
| 도메인 | `.env` 의 `PUBLIC_URL` + [deploy/Caddyfile](deploy/Caddyfile) 의 도메인 + 디스코드 OAuth2 Redirect URL |
| 디스코드 서버/채널/역할 | `.env` 의 `GUILD_ID`, `ADMIN_ROLE_ID`, `*_CHANNEL_ID`, `TICKET_CATEGORY_ID`, `STOCK_ROLE_ID` |
| 메인 패널/실시간 현황 자동 설치 위치 | `.env` 의 `PANEL_CHANNEL_ID`, `STATUS_CHANNEL_ID` (비워두면 건너뛰고, `/setup panel`·`/setup status` 로 원하는 채널에 직접 설치) |
| 판매 코인/체인 | [src/chains/config.js](src/chains/config.js) |
| 수수료·한도·충전 계좌 등 운영 설정 | 관리자 패널 "설정" 탭 (DB에 저장, 재배포 불필요) |

같은 서버에서 **완전히 별도의 운영사로 다시 띄우려면**: 새 디렉터리로 다시 클론 → 새 디스코드 앱(Bot+OAuth) 생성 →
새 `.env` (다른 `PORT`, `DB_PATH`, `GUILD_ID`, 새 핫월렛 키) → 별도 PM2 프로세스 + 별도 도메인/nginx(또는 Caddy) 설정.
DB(`DB_PATH`)와 핫월렛 개인키는 운영사별로 **절대 공유하지 마세요**.
